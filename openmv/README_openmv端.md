> 版本：9.2.17.22（STM32 协议适配版）

> 通信：UART3，500000 波特率

---

## 1. 坐标系统（全局统一约定）

**OpenMV 端所有坐标（cross_x / cross_y / ball_cx / ball_cy）使用同一套约定，无任何取反或换算。**

```
图像绝对坐标：cx_abs ∈ [0,159], cy_abs ∈ [0,119]，y 向下为正
                    ↓ 减中心
中心相对坐标：x = cx_abs - 80   （右为正，范围 -80 ~ +79）
              y = cy_abs - 60   （下为正，范围 -60 ~ +59）
```

| 坐标值 | 含义 |
|---|---|
| y < 0 | 目标在图像上方 |
| y = 0 | 目标在图像中心行 |
| y > 0 | 目标在图像下方 |
| x < 0 | 目标在图像左侧 |
| x = 0 | 目标在图像中心列 |
| x > 0 | 目标在图像右侧 |

**四端完全一致**：内部计算值 = 屏幕显示值 = 串口打印值 = 串口发送值，无任何取反。

## 3. 数据收发

### 3.1 发送帧格式

```
AA AF 30 17 + [23 字节载荷] + sum1 + sum2  （共 29 字节）
```

**帧头**：`0xAA 0xAF 0x30 0x17`（功能码 0x30，载荷长度 0x17=23）

**23 字节载荷布局**（严格对应 STM32 `OpenMV_DataAnl()`）：

| 偏移 | 字段 | 类型 | 字节序 | 说明 |
|---|---|---|---|---|
| [0] | line_state | u8 | — | 0=丢线，1=检测到线 |
| [1] | next_direction | u8 | — | 0=无，2=左转，3=右转 |
| [2-4] | reserved | u8[3] | — | 保留，置 0 |
| [5] | crossflag | u8 | — | 交点有效标志：0=无效，1=有效 |
| [6-7] | angle | s16 | **小端** | 来线倾斜角（度） |
| [8-13] | reserved | u8[6] | — | 保留，置 0 |
| [14-15] | crossx | s16 | **小端** | 交点 x（中心相对，右为正） |
| [16-17] | crossy | s16 | **小端** | 交点 y（中心相对，下为正） |
| [18-19] | reserved | u8[2] | — | 保留，置 0 |
| [20] | red | u8 | — | 当前帧红球数，本程序固定为 0 |
| [21] | blue | u8 | — | 下位机蓝球通道；本程序的黄球数映射至此 |
| [22] | green | u8 | — | 当前帧绿球数 |

**双校验**：
- `sum1` = 累加 frame[0..26]，取低 8 位
- `sum2` = 累加 sum1（每步累加后取低 8 位）

> 注意：STM32 只从该帧取用上表字段；`angle/crossx/crossy` 均为小端。识别层的 `flag=2/3` 在打包时被拆为 `line_state=1` 和 `next_direction=2/3`。

### 3.2 接收

通过 UART3 接收外部命令，在 `UartReadBuffer()` 中逐字节解析。当前版本主要做帧头同步。

### 3.3 硬件连接

| OpenMV 引脚 | 功能 |
|---|---|
| P4 (PB10, UART3 TX) | 数据发送 |
| P5 (PB11, UART3 RX) | 数据接收 |
| GND | 共地 |
| VIN / 3.3V | 供电 |

## 4. 模块功能说明

### 4.1 main.py — 主入口

**职责**：传感器初始化、曝光锁定、主循环调度。

**曝光锁定流程**：
1. 上电先开自动曝光/自动增益/自动白平衡，采集当前环境参数
2. 锁定增益和白平衡
3. 自动校准曝光：以中心 ROI 亮度 L=78 为目标，调整曝光时间（800~10000μs）
4. 锁定曝光后进入主循环

**主循环**（每帧）：
1. 采集图像 → 巡线检测 → 球识别 → 拐角统计
2. 绘制调试信息到屏幕
3. 打包数据通过 UART3 发送
4. USB 串口打印关键调试数据

**关键参数**：
- 目标亮度：`EXPOSURE_TARGET_L_UQ = 78`
- 曝光范围：800 ~ 10000 μs
- 校准 ROI：中心区域 (20, 22, 120, 82)

---

### 4.2 LineFollowing.py — 巡线与交点检测

**职责**：红色引导线检测、来线拟合、交点（拐点）检测。

#### 五区域色块检测

将图像分为 5 个 ROI 区域，从近到远（down→middle→up）顺序检测红色色块：

| 区域 | 位置 | 用途 |
|---|---|---|
| down | 图像下方（近处） | 来线起点 |
| middle | 图像中部 | 来线中段 |
| up | 图像上方（远处） | 来线远端 / 拐点 |
| left | 左侧 | 横臂检测（左弯） |
| right | 右侧 | 横臂检测（右弯） |

#### 来线拟合

- 从底部沿来线向上密集采样，遇展宽突增停止
- 迭代稳健最小二乘拟合 x=f(y)
- 输出：distance（中心处 x 偏移）、angle（斜率角度）、slope、拟合点

#### 交点检测（双路径）

**路径一：双中线拟合法**
- 触发：侧 ROI 检到横臂
- 方法：来线中心线 x=f(y) 与横臂中心线 y=g(x) 解联立方程
- 验证：7×7 邻域在轨验证 + 点到线距离校验（<8px）

**路径二：行走法**
- 触发：不依赖侧 ROI，任意旋转角可用
- 方法：沿来线逐行测横向展宽，第一个展宽突增行即拐点行
- 是倾斜/转弯中段的主路径

#### 卡尔曼滤波与输出

交点绝对坐标经一维卡尔曼滤波平滑后，转为中心相对坐标输出：

```python
Line.cross_x = cx_abs_filtered - 80   # 右为正
Line.cross_y = cy_abs_filtered - 60   # 下为正
```

- 连续 2 帧成功更新才输出 `cross_flag=1`（滤单帧毛刺）
- 丢失后纯外推保持 6 帧（约 200ms），超过则清除跟踪

### 4.3 Colortracking.py — 绿/黄球识别

**职责**：识别绿色和黄色小球，返回数量与主目标球坐标。红色不参与球计数（红色用于巡线）。

#### 多几何过滤

每个候选色块必须同时满足以下条件才被认为是小球：

| 参数 | 值 | 说明 |
|---|---|---|
| 最小像素数 | 35 | 像素阈值 |
| 最小面积 | 55 | 面积阈值 |
| 边长范围 | 6 ~ 60 px | 外接矩形边长 |
| 长宽比范围 | 0.58 ~ 1.72 | 排除长条 |
| 最小填充率 | 0.36 | 面积/外接矩形面积 |
| 最小圆度 | 0.34 | 圆形度 |
| 最小紧致度 | 0.22 | 紧致度 |

#### 轨迹跟踪

- 最近邻关联 + 坐标平滑（2/3 历史 + 1/3 当前）
- 2 帧确认，滤除瞬时反光
- 轨迹保留 8 帧，防短暂漏检导致重复累计

#### 坐标输出

```python
relative_x = track['x'] - center_x   # 中心相对，右为正
relative_y = track['y'] - center_y   # 中心相对，下为正
```

每种颜色返回面积最大的小球位置，供固定长度通信协议使用。

**颜色阈值**（LAB 空间，需现场用 OpenMV IDE 阈值编辑器校准）：
- 绿色：`(30, 100, -80, -15, -20, 70)`
- 黄色：`(50, 100, -20, 25, 25, 127)`

---

### 4.4 CornerStatistics.py — 拐角统计

**职责**：在拐角处统计绿/黄球数量，防止重复计数或漏计。

#### 状态机

```
IDLE → ENTERING → OBSERVING → CONFIRMED → LEAVING → IDLE
```

| 状态 | 触发条件 | 行为 |
|---|---|---|
| IDLE | — | 等待入弯 |
| ENTERING | is_corner=1 连续 2 帧 | 开始观察 |
| OBSERVING | 入弯后 | 持续观察绿/黄球数量，取稳定值 |
| CONFIRMED | 计数稳定 2 帧 或 观察满 24 帧 | 提交计数到累计 |
| LEAVING | is_corner=0 连续 5 帧 | 出弯，回到 IDLE |

## 5. crossx/crossy 数据流

```
图像像素 (cx_abs, cy_abs)  绝对坐标，y向下为正
        │
        ▼  双中线拟合法 / 行走法 求出交点
交点绝对坐标 (cx_abs, cy_abs)
        │
        ▼  一维卡尔曼滤波（x/y 独立）
滤波后绝对坐标
        │
        ▼  连续 2 帧确认 → cross_flag=1
        ▼  减中心 → 中心相对坐标
Line.cross_x = cx_abs - 80   右为正
Line.cross_y = cy_abs - 60   下为正
        │
        ├──────────────────────────────────┐
        │                                    │
        ▼                                    ▼
  屏幕显示 coord_str                    串口打印 Y:%d
  = (Line.cross_x, Line.cross_y)       = Line.cross_y
        │                                    │
        └──────────────┬───────────────────┘
                       ▼
              AnoMessage.FusionDataPack()
              payload[14-15] = crossx  (小端)
              payload[16-17] = crossy  (小端)
                       │
                       ▼
              UART3 发送
```

**关键点**：从 `Line.cross_y = cy_abs - 60` 之后，这个值在屏幕显示、串口打印、UART 发送中**完全一致，无任何取反或换算**。

## 6. 调试指南

### 6.1 串口打印数据

main.py 每帧通过 USB 串口打印调试数据，包含 flag、angle、distance、cross_flag、cross_x、cross_y、green、yellow、ball_status、T_ms 等字段。

### 6.2 屏幕显示元素

| 元素 | 颜色 | 含义 |
|---|---|---|
| 红色十字 | (255,0,0) | 交点位置（cross_flag=1 时） |
| 交点坐标文字 | 白色 | `(cross_x, cross_y)`，中心相对坐标 |
| 蓝色线 | (0,0,255) | 来线拟合结果 |
| 青色框 | (0,255,255) | ROI 检测区域 |
| 绿色/黄色框 | 对应色 | 检测到的小球 |
| 状态文字 | 白色 | flag / angle / distance / 球数等 |

### 6.3 常见问题排查

| 现象 | 可能原因 | 排查方法 |
|---|---|---|
| cross_y 方向反了 | `Line.cross_y = cy_abs - 60` 被误改 | 检查 LineFollowing.py 中 cross_y 计算 |
| cross_flag 一直为 0 | 交点检测未触发 / 确认帧数不够 | 检查 ROI 区域是否覆盖拐点 |
| 球识别误检 | 颜色阈值不准 / 几何过滤太松 | 用 OpenMV IDE 阈值编辑器重新校准 LAB 阈值 |
| 曝光不稳定 | 环境光变化大 | 检查目标亮度和校准 ROI |
| 收不到数据 | 串口接线/波特率不匹配 | 确认 UART3、500000 波特率、共地 |
| 数据错位 | 字节序或偏移错误 | 按第 3.1 节核对，angle/crossx/crossy 均为小端 |

### 6.4 坐标验证方法

1. 将 OpenMV 连接到电脑，打开 OpenMV IDE
2. 手持 OpenMV 对准地面线条，观察屏幕上交点坐标
3. 将交点移到图像右上方，确认 cross_x>0, cross_y<0
4. 将交点移到图像左下方，确认 cross_x<0, cross_y>0
5. 对比串口打印值与屏幕显示值，应完全一致
6. 用逻辑分析仪确认 UART 发送值与屏幕显示值一致
